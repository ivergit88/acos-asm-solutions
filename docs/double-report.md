# Отчёт по double.asm — задание из лекции 03

Повторно проверено 29.10.2026 в WSL Ubuntu-24.04, Linux x86-64,
NASM 2.16.01, GNU ld 2.42. Адреса относятся к эталонному `reference/double`
и стандартной сборке `build/double` из корня репозитория,
собранному без дополнительных флагов из `double.asm`.

## 1. Где находится Result:

Префикс `Result: ` находится в `.rodata`. Его адрес в памяти — **0x402000**,
файловое смещение — **0x2000**, размер — **8 байт**.

```text
52 65 73 75 6C 74 3A 20
 R  e  s  u  l  t  :  пробел
```

Проверка: `strings -a -t x build/double`, `readelf -SW build/double`,
`objdump -s -j .rodata build/double`. В Hex Editor перейти к **0x2000**.
Восемь байтов не включают LF: LF записывается в буфер числа.

## 2. Где деление и зачем обнулять EDX

Цикл получения цифр имеет метку `digits`, начинается по адресу **0x40104F**
(файловое смещение **0x104F**):

```text
0x40104F   31 D2   xor edx, edx
0x401051   F7 F3   div ebx
```

EBX=10. DIV делит не только EAX, а 64-битное составное число **EDX:EAX**
на EBX. Частное попадает в EAX, остаток — в EDX. Перед каждым делением
обнуляем EDX, чтобы старшая половина делимого не содержала предыдущий остаток.
Это важно на каждом проходе, потому что предыдущий DIV меняет EDX.

Для 42: первое деление даёт частное 4 и остаток 2; второе — частное 0
и остаток 4. Из остатков получаются цифры '2' и '4'. Они записываются
в буфер справа налево, поэтому на печать выходит правильное `42`.

## 3. Что в .bss

- `inbuf`: адрес **0x403008**, размер **32 байта** (`resb 32`).
- `numbuf`: адрес **0x403028**, размер **5 байт** (`resb 5`).
- Входной адрес загружается инструкцией **LEA RSI,[rel inbuf]** по адресу
  **0x401004**, файловое смещение **0x1004**. Байты: `48 8D 35 FD 1F 00 00`.

Проверка: `nm -n build/double`, исходник и `readelf -SW build/double`.
В дизассемблере вместо inbuf может быть показан синоним `__bss_start`:
в этой сборке обе метки имеют один адрес 0x403008.

`.bss` — секция типа **NOBITS**: резервирует память, которую загрузчик
обнуляет при запуске. Байтам входного буфера не выделяется содержимое
в ELF-файле. Поэтому нельзя увидеть введённое `21` в Hex Editor файла:
эти байты появляются в памяти только во время read.
Поле Size у символа NASM может быть нулевым; размер буфера берётся из resb.

## Бонус: одинаковые syscall, разные действия

`0F 05` — код инструкции SYSCALL. Номер операции определяется значением RAX:
0 — read, 1 — write, 60 — exit. Остальные регистры содержат аргументы.
В этой программе один read, два write и один exit.
